# Wazuhroom v0.2.0

Concept: WazuhをつかったSOC業務の基本フローと操作方法を体験するコンテンツ / Experience the basic SOC workflow and operations using Wazuh.
Independent bilingual (ja/en) educational simulator. Browser-only offline single HTML, no runtime external dependencies or network. Wazuh 4.14 UI concepts; original implementation, no official logo or source copying. Advisory room, outside main room learning path, profile Other projects alongside hanabi.

## Course and synthetic-data policy
Eight cases: one tutorial, two guided investigations, two checklist investigations, and three independent investigations. The v0.2.0 addition correlates suspicious web-server processes, outbound connections, scheduled-task observations, and execution recurring after a temporary response. HTTP success or file transfer is not proof of execution; a scheduled-task entry is not proof of the launch cause. Initial entry route, root privileges, actor identity, recurrence mechanism, and complete eradication remain unproven unless the authored evidence explicitly supports them.

The added case has internal `revision:2`, with seven required evidence groups (maximum nine selected events), three required references, and three explicit questions: POST destination URI, absolute server-side webshell file path, and full decoded text. HTTP observations, file review, and the publication mapping are separate sources. The Base64 is sent in a POST body, not extracted from the webshell file. Its decoded six-line pseudocode is independently authored inert text describing requested error-display suppression, request-context changes, a mail request, and return-value display. It establishes neither actual source address nor mail delivery. No original code, original Base64, functional webshell, or executable payload is included.

The v0.2.0 release distributes the standalone HTML, source, tests, and public documentation. The English explanatory PDF is a separate requester-review handout outside the repository. Original reference material and private review artifacts remain outside the release.

All case data and supplementary material are original synthetic teaching content informed by generalized behavior patterns. Logs, host snapshots, times, paths, destinations, accounts, process IDs, administrator notes, approvals, and collection assumptions are not original incident observations or Wazuh output converted from real PCAPs. Do not publish original documents, packet captures, images, original commands/payloads, raw identifying strings, or real-to-fictional mapping tables. Public documentation must not identify private source materials or their distribution details.

Review identifiers in names, organizations, hosts, accounts, timestamps, IPs, URLs, paths, email addresses, hashes, wallets, MAC addresses, UUIDs, credentials, headers/cookies, encoded content, and metadata. Omit unnecessary fields; independently invent necessary teaching values. Keep general technical terminology, protocols, and standard field names. Use RFC 5737 documentation ranges for external IPv4 examples and RFC 2606 example domains. No live connections, command execution, malware payloads, claim of exact source reconstruction, or guarantee of complete anonymization of real records.

## Module contract
`src/content.js`: UMD global `WazuhContent` and CommonJS. Exports `{version:'wazuhroom-1',referenceVersion:'4.14',cases:[...],agents:[...]}`. All authored prose `{ja,en}`. Invariant logs/field values remain English and identical in both languages. Each case:
- `id`, `stage` ('tutorial'|'guided'|'checklist'|'independent'), `title`, `brief`, `objectives` (array bilingual), `hints` (3 bilingual), `documents` [{id,title,body}], `agents` (array agent objects), `events` (array), `timeRange:{from,to}` ISO UTC strings, `answer:{verdict,priority,action,target,evidenceGroups:[id[]],documentIds:[id],facts,nextStep,explanation}` prose bilingual. Choice enums verdict incident/benign/unknown, priority high/medium/low, action escalate/monitor/verify. `target` existing agent.id. `steps` [{id,kind,title,body}] where kind 'events','range','search','detail','evidence','document','report'. No magic auto-complete on view: ops recorded by UI after actual user actions. Tutorial uses all 7. Other cases can use subset but always evidence/document/report. `evidenceGroups` AND of OR, max evidence group count + 2. Targets from agents.
- Optional `revision` defaults to 1. Revision 2 cases may define `questions:[{id,label:{ja,en},prompt:{ja,en},acceptedAnswers:[string],multiline?:true}]`. Question answers are case-sensitive exact text after trimming outer whitespace; multiline answers additionally normalize CRLF/CR to LF for comparison. The stored answer retains its original text. This check verifies the submitted text, not analytical reasoning.
- agent shape `{id,name,ip,status,os:{name,platform,version},lastKeepAlive}`. 3-5 agents per case.
- event shape `{id,timestamp,agent:{id,name,ip},rule:{id,level,description,groups,mitre?:{id:[],technique:[]}},decoder:{name},data:{...},full_log,syscheck?:{path,event,sha256_before?,sha256_after?}}`. Rule IDs either verified against official rules or custom 100001+ documented. Include collection conditions in docs. No invented attribution outside recorded fields. Events sorted chronological, unique stable IDs across dataset, 40-80 background events per case. Every critical finding has selectable event ID; docs can be required separately. Answer facts distinguish observed facts and limits.

`src/engine.js`: UMD global `WazuhEngine`, CommonJS, DOM-independent. Public exports:
- `get(object,dottedPath)`
- `search(events,{query:'',filters:[{field,value,negate:false,disabled:false}],from:'ISO',to:'ISO',module:'events'|'fim'})` => filtered array or throw Error. DQL documented subset: field:value, quoted phrase, numeric comparisons > >= < <=, AND OR NOT, parentheses, existence field:*, wildcard * for keyword fields. Typed mapping; unsupported syntax errors, no silent fallback. Unknown fields errors except known supported mapped fields absent in current case.
- `searchAgents(agents,query)` WQL subset fields id,name,ip,status,os.name,os.platform; = != ~ > < and/or parentheses. Unsupported/errors explicit.
- `decodeBase64Text(input)` accepts at most 4096 input characters, removes supported ASCII whitespace, validates standard Base64 and canonical padding, and returns UTF-8 text. Invalid encodings, invalid UTF-8, and unsupported control characters produce errors. The decoder never evaluates code or makes network requests; the UI displays escaped text.
- `createProgress(content)` => `{format:'wazuhroom-save',version:1,dataset:content.version,language:'ja',activeCaseId:content.cases[0].id,records:{[id]:{query:'',filters:[],from,to,view:'overview',evidence:[],documents:[],operations:[],report:{verdict:'',priority:'',action:'',target:'',facts:'',nextStep:''},completed:false,feedback:null,hint:0,expanded:null}}}`. language override UI.
- `assess(caseData,record)` => `{passed,checks:[{key,passed}]}`. Require correct choices, selective evidence AND groups/budget, docs read, all case step kinds except report in operations (actual user action), facts and nextStep structural minimum length 10 (no semantics claimed). Completed flag only if all. Preserve completion on failed later draft? UI sets completed only upon pass and stores submission to allow validate. Engine should snapshot successful record as `completion` in UI, hydration validates snapshot rather than draft.
- Revised records also contain `caseRevision:2` and `report.answers:{[questionId]:string}` with every authored question key present and a 4096-character limit per answer. `assess` appends a `question:<id>` check for each. Unknown or missing answer keys in revision 2 saves are invalid.
- `validateProgress(input,content)` => sanitized deep cloned valid progress or throw. Enforce allowed IDs, limits, filter shape, strings, enum report values, active case, no prototype keys; recompute completion via completion snapshot or record. Legacy imported scores are ignored; completion is recomputed from evidence and checks. Imported invalid leaves UI untouched.
- v0.2.0 keeps save `format:'wazuhroom-save'`, `version:1`, and `dataset:'wazuhroom-1'`. A legacy save containing every original case and missing only `crypto-compromise` gains a fresh unstarted record for that case. A missing original case, unknown case, or active-case selection of the absent new case is invalid. Existing seven-case queries, evidence, reports, successful snapshots, and later review drafts remain subject to validation and are preserved when valid.
- An older `crypto-compromise` record without both `caseRevision` and `report.answers` migrates to revision 2 with empty answers and `completed:false`; its current draft, query, evidence, and opened references remain. A previous completion snapshot, or completed record without a snapshot, becomes `previousSubmission:{caseRevision:1,report:{verdict,priority,action,target,facts,nextStep},evidence,documents}`. This is a historical reference, not a newly validated correct submission. The new requirements must be completed before revision 2 is marked complete. All original seven cases retain their completion behavior; revision 2 saves use strict validation.

Root owns UI/CSS/build/docs. Other agents own content.js and engine.js with dedicated tests. All filenames no external packages except optional jsdom development tests. Node built-in tests. Distribution `wazuhroom.html`, `docs/index.html`, `docs/wazuhroom.html` all identical. Language switching preserves query/report/current UI state and completion, initial ja if navigator primary language starts ja else en. Auto-save own key; JSON export/import with backup and confirmation; file:// no external loads. Accessibility semantic controls, visible focus, reduced motion. Tutorial guide panel separate from Wazuh-style application area.
